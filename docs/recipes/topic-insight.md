# 配方：主题洞察

**场景**：你记得「某个问题/方案」以前聊过，但想不起来在哪个 Agent、哪次对话里。
让 Agent 按主题把散落在多家 Agent 里的讨论汇成一条时间线。

## 提示词（复制给 Agent）

```text
围绕关键词「{{关键词}}」做一次跨 Agent 主题回顾。

项目：{{项目路径}}（如果不想限定项目，写「全部项目」）

步骤：
1. 调 search_sessions 搜索关键词，拿命中会话和摘录；
   如果结果太多，可以按 agent 过滤或缩小关键词。
2. 对命中较多的会话，用 read_session 读相关段落（一次不超过 8000 字）；
   必要时用 project_timeline 看它们的时间顺序。
3. 归纳这个主题：
   - 被讨论过几次、每次的结论是什么
   - 有没有前后矛盾、后来被推翻的结论
   - 哪些问题一直没解决

输出：
- 时间线：按日期列关键节点（标会话 id）
- 共识：多次对话里一致认可的结论
- 分歧 / 变化：说法前后不一致的地方
- 仍然没解决的

规则：每个结论标会话 id；找不到就写「记录里没有」；
不要把不同 Agent 的推测当成事实，不要把一次对话的结论说成所有对话的共识。
```

## 工具顺序

| 步骤 | 工具 | 用途 |
|---|---|---|
| 1 | `search_sessions` | 全文搜索，返回命中摘录 |
| 2 | `read_session` | 读命中会话的相关段落 |
| 3 | `project_timeline`（可选） | 确认讨论的先后顺序 |

## 为什么有效

- `search_sessions` 同时覆盖主会话和子代理会话，结果里带来源标记；
- 先搜索再读，不用把整个项目扫一遍；
- 时间线能看出「结论是什么时候变的」——这比单次摘要更有价值。
