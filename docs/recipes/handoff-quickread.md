# 配方：接手前速读

**场景**：你要接手一个别人做过的项目。上一位可能用 Codex 做了一半，换成了 Claude Code，
又换成了 Qoder——现在轮到你。先别急着读代码，先搞清楚「上一段到底做到哪」。

## 提示词（复制给 Agent）

```text
你是刚接手这个项目的工程师。先用 agent-archive 的 MCP 工具了解现状，不要一上来读全文。

项目：{{项目路径}}

步骤：
1. 调 project_brief，读上一位 Agent 最后一段做了什么：
   - 最后停在哪个会话、最后一句用户说了什么
   - 这一段动过哪些文件
   - 留下哪些未完成任务
2. 如果有未完成任务或读不懂的地方，用 search_sessions 找相关会话，
   再用 read_session 只读必要段落（一次不超过 8000 字，按需分段）。
3. 如果 read_digest 有现成的项目摘要，先读；没有就跳过，不要自己编。

输出：
- 一句话：上一位做到哪
- 已改动文件（只列你能在工具结果里确认的）
- 未完成 / 待确认事项（逐条标出处：会话 id 或文件名）
- 建议的第一步（最多 3 条，明确标成「建议」）

规则：只依据工具返回的事实；没查到就说「记录里没有」；不要猜。
```

## 工具顺序

| 步骤 | 工具 | 用途 |
|---|---|---|
| 1 | `project_brief` | 一页事实：上一位、文件、任务、最近会话 |
| 2 | `search_sessions`（可选） | 按关键词找相关会话 |
| 3 | `read_session` | 只读必要段落，默认截断 |
| 4 | `read_digest`（可选） | 有现成摘要就读，没有不生成 |

## 为什么有效

- `project_brief` 是**确定性**的，不调模型、不花钱，先拿它当「交接单」。
- `read_session` 默认只给 8000 字，超出会报 `hasMore` / `nextOffset`，
  避免一次性把十几万字的会话塞进上下文。
- 先看事实再决定读哪场，比从第一场开始读省一个数量级。
