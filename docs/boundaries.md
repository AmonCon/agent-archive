# 边界与隐私：它读什么、写什么、联什么网

这个文件存在的理由：一个工具说「只读」很容易，说清**具体读到哪一层、写到哪个文件、什么时候联网**才有用。下面每一条都可以在代码或测试里核对。

## 读什么

| 读什么 | 位置 | 说明 |
|---|---|---|
| 各家 Agent 的会话文件 | 各自的默认存储目录（见 README「当前支持」表） | Claude Code / Codex / Cursor / Gemini CLI 等 21 家 |
| 环境变量 | `CODEX_HOME`、`CLAUDE_CONFIG_DIR`、`DSH_HOME` 等覆盖变量 | 只用于**定位目录**，不读它们的值当数据 |
| 各家 MCP / 技能 / 记忆 / 渠道 / 斜杠命令配置 | 各自的配置文件 | 只读**元数据**：键名、条目名、路径、长度、哈希 |
| 你显式给的目录 | `--source <目录>` | 备份、导出的会话包、任意目录 |

**读不到的东西**：凭证的**值**。`env mcp` 只给环境变量**键名**，`env providers` 只报凭证形态（`inline` / `env` / `oauth`）与变量名。`secrets` 扫描会找到明文凭证，但输出一律掩码——这个工具不能自己变成泄漏渠道。

## 写什么

只写**自己的状态目录**，默认在 `~/.agent-archive/`（可用 `AGENT_ARCHIVE_HOME` 改）：

| 路径 | 内容 | 丢了会怎样 |
|---|---|---|
| `cache/scan-v*.json` | 会话扫描结果缓存 | 下次全量重扫，慢一点 |
| `cache/inventory-v*.json` | 能力面缓存 | 同上 |
| `index/fulltext-v1.sqlite` | 全文索引 | 跑一次 `index` 重建 |
| `pricing.json` | 价目表 | 重新 `pricing sync` |
| `upstream-cache/` | 上游参照项目的镜像 | 重新 `refresh.mjs` |

全部是**派生数据，都能从源头重建**。删掉整个 `~/.agent-archive/` 只会让你重扫一次。

**绝不写**：

- 任何 Agent 的会话文件、配置文件、数据库
- 任何 Agent 的技能 / 命令 / MCP 目录
- `connect` 只**打印**配置片段，不写入任何文件（有测试专门锁这一条）
- 不给任何 Agent 注入上下文、不改写请求、不做代理转发

## 联什么网

**默认完全不联网。** 只有一个例外：

| 命令 | 联网吗 | 说明 |
|---|---|---|
| 除下面两行之外的所有命令 | ❌ | 纯本地读文件 |
| `pricing sync` | ✅ 一次 | 拉 models.dev 的公开价目表（约 6 MB），**只下载不上传** |
| `digest --run` / `refresh --run` | ✅ | 用**你自己配的** API Key 调模型，不经过我们的任何服务 |

没有账号、没有服务端、没有遥测、没有崩溃上报。`serve` 只监听 `127.0.0.1` 并校验 Host 头（防 DNS rebinding），只处理 GET/HEAD，没有任何写接口。

## 它不是什么

- **不是记忆注入工具。** 它不往任何 Agent 里塞上下文。要不要读、读多少，由那个 Agent 自己通过 MCP 决定。
- **不是聊天备份的消费级产品。** 不采集网页版 AI 对话（那要往别人页面注入脚本），只管本机 Agent 的会话文件。
- **不是检索增强/向量库。** 有全文搜索（SQLite FTS5），但没有 embedding、没有 RAG 管线、不做召回注入。
- **不是网关，也不是代理。** 不转发任何请求，不接管流量，不碰你的模型账单。
- **不是实时监听。** 按需扫描 + 缓存（会话层按文件指纹、环境层 5 分钟），不是文件监听守护进程。
- **不破解加密。** Trae / Windsurf 的会话库是加密的，明确不解，`doctor` 如实报「确认读不了」而不是假装成功。

## 这个工具最容易犯的错，以及怎么防

三类错误在只读工具里最危险，因为**它们不报错，只是给出错误结论**：

1. **把「读不到」当成「没有」。** 权限不足、文件正在写、格式变了，都会被折成 `0`。所以环境层每个文件/目录都带 `ok / missing / unreadable / unparsable` 状态，未知单独计数；会话层 `discover` / `stat` 失败会保留上一轮结果并计入 `problems`，只有 `ENOENT` 才算删除。
2. **把「索引里没有」当成「不存在」。** 搜索结果带 `index: {docs, total, failed, builtAt}`，空结果时明确说「索引覆盖 N/M 场」。
3. **把不同口径的数字混在一起算。** 各家 `input_tokens` 有的含缓存有的不含，所以每条记录都带 `semantic`，语义未知的行不进缓存命中率；没报成本不等于 0 元。

这三条在 `doctor` / `env audit` / 搜索输出里都能直接看到，不是文档里的承诺。
