## 1. 已落地（本轮）

### 1.1 搜索：报出覆盖率与新鲜度（P0）

**问题**：只报 `hits` 时，「这场会话没进索引」和「这场会话没说过」长得一模一样。

上游依据：magpie 的 `said_index.go:55-67,541-589`——`SaidFound` 带
`indexed / total / listing / cut`，首次检索只等 2 秒，拿到多少答多少。

改动：
- `src/search.js`：`buildIndex()` 把 `total_sessions` / `failed` 写进 `meta`；
  `search()` 返回 `index: {exists, docs, total, failed, builtAt}`；`indexStats()` 复用同一份口径。
- `src/mcp.js`：`search_sessions` 返回 `index`；空索引的 hint 改为
  「建一次之后日常只需增量更新」。
- `src/cli.js`：搜不到时补一行 `索引覆盖 N/M 场（K 场读不出）· 建于 …`；
  有结果时也把同一行放进页脚。

验收：`test/search.test.js` 新增用例——建索引后 `docs=2/total=2`；再新建一场但不重建，
搜索结果仍如实说 `2/2` 而不是假装覆盖 3 场。

### 1.2 `read_session` 支持 `find`（P1）

**问题**：搜索结果给的是片段，打开会话只能从头读。

上游依据：`sessions_mcp.go:216-274`、`transcript.go:78-139`——`find` 从命中前 3 条开始，
并告诉页面「前面还有 N 条」。

改动：`src/mcp.js` 加 `find` 参数与 `find: {query, matchedMessage, startMessage}` 返回；
找不到时给 `code: 'find_not_found'` 而不是静默从头读。渲染层拆成
`renderMessageChunks()`（每条带 `messageIndex`），`renderMessages()` 变成它的 join，
输出字节不变。

验收：`test/mcp-read-find.test.js`（新增 2 条）——7 条消息里搜第 5 条，窗口从第 2 条开始、
更早的不出现；找不到时 `isError: true` + `find_not_found`。

### 1.3 Claude 分叉/复制的 token 重复计（P0，数据正确性）

**问题**：`--fork-session` / `/branch` 整段复制历史，`usage.js` 按文件各建一个 `seen`，
同一 `message.id` 在原件与副本里各算一次。

**实测（本机 2 个 Claude 文件 / 149 条 usage 行）：44 个唯一 id、105 条重复。**

上游依据：`cc_copies.go:335-397`——`ccRest` 只统计「副本有、keeper 没有」的消息。

改动：`src/usage.js` 的 `seen` 提到所有文件之外（`message.id` 本来就是每次回复的唯一标识），
保留「同 id 取 output 最大」；出 rows 的循环也移到文件循环之外。

验收：`test/usage.test.js` 新增用例——原件（m1 流式两次）+ 完全复制 + 分叉（m1 + 新 m2），
断言 2 行而不是 4 行，fresh/output/cacheRead 各自对上。

### 1.4 WorkBuddy 用量源（P0，功能缺口）

**问题**：我们认 WorkBuddy 的会话，却把它的用量算成 0。

上游依据：cc-switch `session_usage_workbuddy.rs:1-12,83-111`、`providers/workbuddy.rs:220-344`。

改动：`src/usage.js` 新增 `readWorkbuddy()` 并注册进 `SOURCES`。口径：
- `rawUsage` 记在每请求最后一个事件（assistant message 或 `function_call`）；
- `prompt_tokens` 含缓存 → `semantic:'total'`，由 `normalizeFresh` 减；
- `completion_tokens` 已含思考 token，`reasoning_tokens` 只单列；
- 缓存读取四个字段取最大（`prompt_cache_hit_tokens` / `cache_read_input_tokens` /
  `cached_tokens` / `prompt_tokens_details.cached_tokens`）；
- 无 `rawUsage` 时退回 SDK 的 `providerData.usage`（`inputTokensDetails[].cached_tokens`）；
- 子代理文件算父会话；按事件 id 批内去重；
- `credit` 是积分不是钱，`cost: null`。

验收：`test/usage.test.js` 新增用例（含重复事件、子代理、SDK 回退、`custom-local:` 前缀剥离）。
本机真实数据：**1288 条请求 / 未缓存输入 935.8 万 / 输出 102.6 万 / 缓存读 1.27 亿 / 成本未知 1288 条**。

### 1.5 斜杠命令盘点（P1，新资产类）

上游依据：magpie `commands.go:61-146`、`command_import.go:96-110,178-322`。

新增 `src/env/commands.js`（零依赖、只读）+ `test/env-commands.test.js`（12 条）。
读 6 家：Claude Code / OpenCode（含 `command/`）/ Pi（`prompts/`）/ Gemini CLI（TOML）/
Qwen Code（md + toml）/ Factory Droid；Codex `~/.codex/prompts` 只列 `legacy: true` 不解析。

三条设计决定：
1. **正文绝不出模块**：只给 `promptLength`（UTF-8 字节）与 `hash`。测试里用 8 个哨兵字符串
   扫 `JSON.stringify(结果)` 断言不存在。
2. **同名同内容合并、同名不同内容 `conflict: true`**：`hash = sha256(description + "\0" + prompt)`，
   与 `skills.js` 的 `groupByHash` 同一套身份模型。
3. **missing ≠ unknown**：目录不存在是正常状态（没装/没定义），只有 EACCES / 坏 TOML 进 `errors`。

接线：`inventory.js`（`fullInventory` / `summary` / 每 Agent `capabilities.commands` /
`auditEnvironment` 两条检查）、`cli.js`（`env commands`）、`mcp.js`（`inventory type=commands`）、
`server.js`（`/api/env?tab=commands`）、`pages.js`（`/env?tab=commands`）。

本机实测：**1 条命令（Claude 的 `/commit`）/ 1 份文件 / 12 个根 missing / 0 未知**。

### 1.6 环境层存在性清单补齐（P0，覆盖面）

**问题**：`registry.js` 认得 21 家扫描器，`env/inventory.js` 的 `AGENT_PRESENCE` 只有 12 家。
会话层认得 WorkBuddy/Pi/Kimi，能力面里却找不到它们。

上游依据：cc-switch 的 `ToolSpec` 纪律——**名字只有一张表，表生成 fixture、两侧都测**
（`commands/misc.rs:170-214,4808-4826`）。

改动：补 WorkBuddy / CodeBuddy / Pi / Oh My Pi / Kimi / Grok Build / MiniMax Code / Cline /
OpenClaw 的 presence 与显示名（12 → 21 家）；加契约用例「scanners 里每个有名字的扫描器，
都必须在 `AGENT_PRESENCE` 里声明且有 `DISPLAY`」；`INVENTORY_CACHE_VERSION` 2 → 3。

本机实测：能力面从 12 家变 **14 家（有数据的）**，新增 WorkBuddy（4 个技能）与 Pi（27 个 junction）。

### 1.7 失败不能当删除（P0，数据完整性）

**问题**：`registry.js` 两处把"读不到"当成"没有了"——discover 抛错当空列表、
`statOrNull()` 吞错误后直接 continue。

上游依据：cc-switch `providers/utils.rs:14-50`（`NotFound` 才算空，其他 I/O 错误一律
`incomplete`）、`mod.rs:136-143`（失败的 worker 不据此删会话）。

改动：
- `statOrNull()` 带 `{code, reason}`；只有 `ENOENT` 算删除，`EACCES/EPERM/EBUSY` 保留旧
  session、计入 `keptStale`、记 `problems`（`kind:'stat'`）。
- `discover()` 抛错时把该家旧缓存原样搬回、记 `problems`（`kind:'discover'`），不清空。
- `doctor.js` 的 `summarizeProblems` 补两种 kind 的中文标签 + 一句
  「已沿用上一次扫描结果，没有被当成删除」。

验收：`test/registry.test.js` 新增 3 条（discover 抛错保留缓存 / EACCES 保留 / ENOENT 正常删）。

## 2. 没落地（明确记录）

| 项 | 不做的理由 |
|---|---|
| magpie 的二进制解析缓存 | 我们的 `scan-v5.json` 只有 3.29 MB，parse 24 ms / stringify 15 ms；零依赖 + 可读性更值钱。若 >20 MB 或 parse >100 ms 再评估。 |
| `said-v1.db` 的"只存词、不存正文" | 它的前提是"查询时回源可接受"（6 秒预算）。我们索引同时承担 BM25/摘录/正文缓存，回源读 zstd 单帧成本远高。 |
| slash commands 写侧 | 只读档案馆，不写任何 Agent 的 commands 目录。 |
| WorkBuddy 额度（WBIPC + HMAC） | 要连本地进程、读凭据、发请求。只借四个状态词汇。 |
| cc-switch 锁恢复 / panic 回滚 / `write_and_commit` | Node 无 `Mutex` poison，也不写用户文件。`registry.saveCache()` 的 tmp+fsync+rename 更强。 |
| Antigravity 的 `session_log_sync` 游标 | 我们没有用量账本表。只借一条：伴生库（`conversations/<id>.db` + `-wal`）必须一起进缓存指纹。 |
| Chat Memo 的消费级定价 / 浏览器插件 / 绝对化话术 | 与我们定位冲突；它的隐私政策自己就承认会经 Cloudflare 转发。 |

## 3. 下一步（从 findings 里挑出来的、本轮没做的）

按价值排序，都还没动手：

1. **`skills.js` 的 `treeHashOf` 移出列表路径**（列表查询别做重活）。现在只在
   "同 SKILL.md 哈希、不同 realPath"时才触发，但一次全量 inventory 仍可能读多份
   技能树（每份上限 8 MB / 400 文件）。
2. **搜索片段按 role 优先级截取**（现在 `indexOf` 第一次出现，可能命中工具输出）。
3. **若接 Qoder 用量**：credit-only 记录也是调用，不能用 `tokens_used > 0` 过滤。
4. **若接 Antigravity 用量**：伴生库 `conversations/<id>.db` + `-wal` 必须一起进
   缓存指纹，否则"转录没变、原生库后到"会永久缺 model。
5. **`env audit` 可加一条 DSH `.lock` 只读诊断**（读 PID + mtime，报"有活锁/stale 锁"），
   解释"为什么设置保存不了"。
6. **产品化**：README 首屏重排 / 配方前置 / 边界卡 / npm 发布 + CHANGELOG /
   `agent-archive connect` / `demo` + 空状态 / `serve --open`。
