## 0. 本轮问题

用户这轮的要求是：学习两家"如何获取各个渠道、各个 Agent、会话、MCP、技能等工具"。
会话层（sessions）在前四轮已经做透；这一轮的落点是**环境层**——`src/env/`。

两家的共同答案，恰好也是我们最缺的：

1. **MCP 不是一个 `mcpServers` 文件，而是十几家各不相同的格式/位置**。
2. **"读不到"不能当成"没有"**（magpie 的 `ErrUnreadable`、cc-switch 的
   `AppError::Config/Io{path}` 都是踩过事故写下的）。
3. **能力要带状态和原因**，不是一个数字。
4. 模型**渠道**（provider）是可以跨 Agent 归一的，不是每家一份配置。

### 1.2 校验与"未知"：不再静默跳过

- 缺 `command`/`url` 的条目 → `invalid[]` 计数并给出原因，不混进服务数。
- stdio 的 `command` 做**静态 PATH 检查**（只查文件存在性，**绝不 spawn**）：
  `commandFound:false` 会在 `env audit` 里解释"为什么它启动失败"。
- 文件状态分 `ok / unreadable / unparsable`；`mcpSummary.filesUnknown` 单独计数。
- 技能根同样分状态（`rootsUnknown`），技能 frontmatter 新增
  `disable-model-invocation` → `manualOnly`。
- `env audit` 新增 3 条检查：坏条目、命令找不到、未知来源。

### 1.3 渠道层（新文件 `src/env/providers.js`）

回答"模型从哪儿来"：同一 `base_url` 的多家配置**归并成一个渠道**，
显示哪些模型、哪些 Agent、凭证是 `inline/env/oauth`、环境变量叫什么。

已支持 7 家原生配置：Claude Code（`env.ANTHROPIC_BASE_URL`）、Codex
（`[model_providers.*]`）、Qoder（`providers{}`）、OpenCode（`provider{}`）、
Hermes（`config.yaml providers:`）、DSH（`settings.yaml` 根下的 `providers:`）、
Kimi（`config.toml [provider]`）。

本机实测：**3 个渠道、11 条配置、5 家 Agent 在用**——
`magpie` 本机网关（codex/dsh/hermes/qoder）、`嘻嘻-claude` 中转
（claude-code/hermes）、`magpie-anthropic`（dsh/hermes）。
其中一条中转站在两家各配了一遍，被正确归并成一个渠道。

安全：URL 去 query/账号密码，apiKey 只判断"有没有"、绝不回传值。

### 1.4 技能：整树哈希 + 手动技能

- 两份技能 `SKILL.md` 完全相同但脚本不同 → 用**整树哈希**再分一次，
  不再被合成"一个能力"（排除 `node_modules`/`.git`/`__pycache__`/`dist` 等）。
- `manualOnly`：`disable-model-invocation: true` 的技能不算"模型可主动使用"的能力。

### 1.5 命令入口

```
agent-archive env providers        # 渠道清单
agent-archive env                  # 总览里多一行「渠道 N 个（M 条配置）」
agent-archive env audit            # 多 3 条检查
MCP inventory type=providers       # 模型侧也能查
```

## 2. 没落地（明确记录）

| 项 | 不做的理由 |
|---|---|
| MCP 真连通性探测（initialize/tools.list） | 要 spawn 用户配置里的任意命令、发带凭据的请求。档案馆是只读查看器，这等于给配置文件一个本地代码执行入口。**只做静态检查**（命令是否存在、URL 是否合法）。 |
| `skill-router` / `mcp-router` 的写侧 | 它们是网关能力：往 Agent 目录写链接、起进程池、做鉴权。我们不改用户配置。 |
| per-agent 完整能力快照（`AgentView` 那套 9 种状态） | 方向对，但一次做完太大；本轮先把"未知"和"渠道"两个事实层补齐。下一轮可以把 `agents[]` 升级成 `{state, items, problems}`。 |
| 技能 `enabled/disabled` 的完整语义（各 Agent 的 `skillOverrides`） | 需要逐家读项目级配置；本轮只做 frontmatter 的 `disable-model-invocation`。 |
| 内容哈希 revision 检测外部改动 / 残留 tmp 诊断 | 属于写侧场景；我们只读，收益低。 |
