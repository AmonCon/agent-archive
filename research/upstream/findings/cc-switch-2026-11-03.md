## 一、本轮结论摘要（10 条）

1. **Grok 解析从「整文件封顶就整文件跳过」改成「逐行流式 + 单行上限 + 字节游标」**。旧代码
   `> 50 MiB 直接 return`（静默漏记后续全部 token）；新代码单行上限 8 MiB，超长行丢弃但
   **游标照常前进**，后续用量事件不受影响。这是「上限加在记录粒度，不加在文件粒度」的完整样板。
   `session_usage_grokbuild.rs:148-152, 390-391`
2. **游标只推进到「最后一个完整行之后」**；未写完的尾行把游标停在行首，下一轮补全再解析。
   反过来按行号计数会把半行计入，那一行补全后**永久丢失**。`session_usage_grokbuild.rs:288-291`；
   同一条纪律在 Claude 路径写作 `session_usage.rs:625-628`
3. **沉降窗（deferred）不再靠「整文件重扫」兜底**：遇未沉降事件即停，游标不越过该行；且
   **推进游标但保留旧 mtime**，这样文件不再增长时沉降窗到期仍能续读。`session_usage_grokbuild.rs:306-311, 375-378`
4. **解析器语义升级 = 游标标记换代 + 一次性重扫 + 持久去重账本**。Pi 把旧标记 `0b101/0b110`
   升到 `0b111`，旧游标重扫一次（`(0,2)`），再跑一次 `(0,0)`；历史靠 request 台账不变。
   `session_usage_pi.rs:37-43, 176-186`（测试 `old_cursors_rescan_once_without_changing_existing_history`）
5. **Codex 有界分叉改成「验证式接受」**：只有父文件**物理前缀完整**（按字节读到 `end_byte_offset`、
   `ordinal` 连续、首记录就是父 meta）**且继承计数基线精确相减相等**时才认，任何一条不满足就退回
   deferred；并且「绝不改写 rollout 数据」。`session_usage_codex.rs:1991-2008, 2220`
6. **deferred 是一等状态**：`PendingReason::{MissingParent, Stable, Retryable}` 三态 + 只在
   reason **变化时**才 `log::warn` 一次，不会每轮刷同一条日志。`session_usage_codex.rs:1923-1957`
7. **路径别名去重**：symlink / Windows junction / 8.3 短名 / 大小写别名会让同一文件在候选表里
   出现两次，导致同一把 `<file>.lock` 被取两次、**每次写都报假冲突**。修法是「realpath(父目录)
   + 文件名」当身份。`dsh_config.rs:39-43, 62-76`
8. **补齐字段只填不清**：Antigravity 的耗时/首字用 `latency_ms=CASE WHEN ?13>0 THEN ?13 ELSE
   latency_ms END, first_token_ms=COALESCE(?14, first_token_ms)`；原生库读不到时**保留已存值**。
   `session_usage_agy.rs:225`；MCode 用**独立水位 + 10 分钟沉降窗**只回查最近几分钟的行
   `session_usage_mcode.rs:113-122`
9. **跨源去重的放宽条件要带闸门**：模型别名只在 `app_type='codex' AND data_source='codex_session'`
   时放宽，且 `NULLIF(TRIM(...))` 排除空白、显式排除 `unknown`；测试锁住「gemini 不得走这条别名」。
   `usage_stats.rs:482-508, 713-729`
10. **失败可见性有两种正当形态**：多源取数失败要**汇总所有源的失败**再上抛
    （`exchange_rates.rs:118-136`「获取汇率失败（open.er-api.com: …；floatrates.com: …）」）；
    而 MCP 连通性探测**故意只给红/绿、不返回也不记录传输错误**，理由是 URL/header/参数可能含凭据
    （`mcp_connectivity.rs:101-104`）。两者都要显式写在代码里，不能靠默认。

## 三、逐条证据

### 3.1 增量与游标（本轮最值得抄的一类）

**(a) 字节游标的正确性规则（Claude 路径，旧 pin 已有，本轮被 Grok 复用）**

> 增量语义：游标是字节偏移（`last_byte_offset`），文件追加时 seek 到游标只读新增尾部，
> 避免活跃会话文件每轮被整文件重读。游标只推进到最后一个完整行（以 `\n` 结尾）之后——
> 按行号计数的旧游标会把未写完的半行也计入，导致该行补全后被跳过、记录永久丢失。
> —— `session_usage.rs:625-628`

> 不能回退全量重读：`rollup_and_prune` 会把 30 天前的明细汇总后删除，request_id 去重只查
> 明细表、对已剪条目失明，重导会在下次 rollup 时二次累加、永久放大统计。代价是旧行号游标
> 半行 bug 吞掉的历史行无法找回（无持久账本时与已剪条目不可区分，双算比丢行更糟）。
> —— `session_usage.rs:630-635`

这两段是「增量为什么不能拿全量重读兜底」的完整论证，也是我们目前没有的论证：
我们的缓存每轮都按 `(mtime, size)` 全量重解析，**没有剪枝**，所以全量重读永远安全。
这条差别要写清楚，否则照着抄会引入不存在的约束。

**(b) 上限的粒度：文件 → 行（Grok 本轮新增）**

> 单行上限。turn_completed 用量事件只有几 KiB；超限的是工具结果/正文载荷行，跳过不解析。
> 禁止整文件 `read_to_string`——Grok 活跃会话的 updates.jsonl 几天就能到几十～上百 MiB，
> 50 MiB 整文件封顶会把后续 token 全部漏记。
> —— `session_usage_grokbuild.rs:148-152`

> 读一行，超长则丢弃内容只计消耗字节，避免工具载荷把进程内存打满。
> —— `session_usage_grokbuild.rs:390-391`（`read_capped_jsonl_line`，实现见 `:391-439`）

配套的处置（每一条都有测试锁住，测试名直接写进文件）：
- 未写完的尾行：「未写完的尾行：游标停在行首，下一轮补全后再解析。」`:288-291`
- 文件被截断：「文件被截断，游标钉至 EOF、不重放旧区间」`:230-236`
- 沉降窗停下：「沉降窗：…遇到第一条未沉降的事件即停…游标不越过该行，下一轮从这里续读，
  不再整文件重扫。」`:306-311`
- defer 时仍推进游标：「推进字节游标、保留旧 mtime：文件不再增长时沉降窗到期仍能续读。」`:375-378`
- 幂等键不能撞：「增量续读时全局序号未知，改用行首字节偏移，避免与文件前部的 idx 撞键。」
  `:340-347`

**(c) 旧游标迁移：只做一次性补齐，不回头重导**

> 升级前 Grok 把 last_line_offset 写成「已解析事件数」而不是行号/字节。有字节游标后不再读它。
> NULL 时跳过前 N 个 turn_completed，补进 50 MiB 封顶漏掉的后续轮次；不能从头重导——
> rollup 剪掉明细后会双算。 —— `session_usage_grokbuild.rs:220-222`

**(d) 解析语义升级用「标记换代」而不是「全量重算」（Pi）**

> Flavors importing official subagent tool results rescan older cursors once to recover
> previously ignored subagent usage. The durable request ledger keeps already imported
> history unchanged. —— `session_usage_pi.rs:40-43`

> 旧标记 `0b101`（legacy）/ `0b110`（compat）/ 新 `0b111`（subagent）；
> `accepts_revision_marker()` 决定这个 flavor 接哪些标记 —— `session_usage_pi.rs:37-43, 176-186`

关键在**前提**：得有持久去重账本（`session_usage_dedup` / `PI_REQUEST_DEDUP_SQL:45`）才能
「重扫一次而不双算」。测试直接断言 `(0,2)` → `(0,0)`：第一次重扫 2 条被 skip，第二次什么都不做。

### 3.2 解析正确性与边界

**Codex 有界分叉：宁可 deferred 也不猜**（`session_usage_codex.rs:1991-2109`）

> A bounded-reference fork stores only its own requests. Accept this narrow case only with a
> complete physical prefix and an exact inherited counter baseline. Otherwise retain the
> existing replay/deferred path. Never rewrite rollout data. —— `:1991-1993`

校验清单（任何一条 `?` 失败即 `return None`，走老的 deferred 路径）：
1. `history_base.thread_id == parent_id`（`:2002`）
2. `end_byte_offset ∈ (0, 64MiB]`、`end_ordinal_exclusive > 0`（`:2005-2009`）
3. 每条 token 事件与 usage 记录都带 `last.input/output` 分项、且时间戳晚于 fork 点（`:2012-2026`）
4. 用第一条事件反推继承基线 `baseline = total - last`，逐项 `checked_sub`（`:2018-2023`）
5. 父文件按字节读到 `end`，逐行验 `ordinal` 连续、首记录必须是父 `session_meta`（`:2036-2064`）
6. **读完再验一次父文件 stamp**（`ParentFileStamp::from_file` 前后比对）防验证期间被改（stamp 捕获 `:2050`、读完复验 `:2096-2098`）
7. 父最终 `total_token_usage` 必须与 `baseline` 精确相等（`:2099`）

这条对我们最有用的是**第 6 条**：验证依赖另一个文件时，读完要重验「验的时候它没被改」。
我们的旁路库 enrich（`scanners/codex.js`）也在跨文件取真值，但没有这个前后 stamp 比对。

**「和总数相加」的重复计数陷阱（Pi 官方 subagent 扩展）**

> if has_request_usage { continue; } // `result.usage` is the sum of these requests.
> —— `session_usage_pi.rs:756-757`

> The parent entry is written after the entire task; it is not a per-request end time.
> Never infer latency from it. —— `session_usage_pi.rs:740-741`

> Only recognize the official example extension's tool-result contract. … Do not walk arbitrary
> details/compaction snapshots looking for `usage`. —— `session_usage_pi.rs:685-693`

翻译成可迁移的三条：**子项和汇总同时存在时只取子项**；**父条目时间戳不能当子请求结束时间**；
**只认一种已知契约，不要满树搜 `usage` 字段**。

**退化字段不要连带毁掉主字段（Antigravity protobuf）**

> Field 11 is the wait for the first token and field 12 the rest of the stream; … Decoded on their
> own so an unexpected wire type there can never hide the model name. —— `native_models.rs:47-49`

测试里还专门造了「field 11 用错 wire type」的样本，断言模型名照常读出来（`native_models.rs`
测试 `reads_first_token_and_streaming_durations_without_hiding_the_model`）。
**新字段的解析失败必须局部化，不能把同一 record 里已经能读的字段一起判死。**

**跨源去重的闸门（usage_stats）**

> 常规路径按上游回显模型匹配。仅 Codex 会话允许再匹配代理记录的请求模型：Codex rollout 保留
> 客户端别名，而代理 `model` 可能已被映射为实际上游模型。空白或 `unknown` 请求模型不能放宽
> 匹配，避免无有效别名时扩大启发式去重范围。 —— `usage_stats.rs:482-486`

实现里 `session_app_type='codex' AND session_data_source='codex_session'` 三重限定
（`:487-508`），`DedupKey` 也加了 `data_source` 字段（`:713-729`）。
测试 `test_effective_filter_dedups_only_codex_request_model_alias` 明确断言 **gemini 的同形
别名不得被去重掉**（`:3471-3560`）。这就是「放宽条件必须有反向测试守住不外溢」。

### 3.3 失败可见性

**(a) 好样板：多源取数汇总失败**

> 依次尝试主源和备用源，用第一个能解析出目标币种的。
> 两个都失败就返回错误，由前端继续用上次缓存或手填的汇率，不影响记账。 —— `exchange_rates.rs:102-104`

> `Err(AppError::Message(format!("获取汇率失败（{}）", failures.join("；"))))` —— `:132-135`

配套：`pick_target_rates` 丢掉 `!is_finite() || <= 0.0` 的汇率（`:37-46`）；
两个 parser 都以 `(!rates.is_empty()).then_some(rates)` 结尾（`:55, :66`）——
**「解析出来是空集合」按失败处理，不是「成功但没数据」**。

**(b) 反例但有正当理由：MCP 连通性探测**

> Do not return/log transport errors: URLs, headers and process arguments may contain
> credentials. The UI only needs a red/green connectivity result. —— `mcp_connectivity.rs:101-104`

这是「失败可见性 vs 凭据泄露」的显式取舍：宁可只给布尔，也不把可能含 token 的错误写进日志/界面。
对照我们的 `doctor`：错误文本里可能带用户路径、env 值、命令行参数。**该脱敏后再可见，
而不是二选一**；cc-switch 选最保守那一档是因为它的定位不需要诊断，我们需要。

**(c) deferred 的告警去噪**

> `should_warn` 只在 `pending` 表里的 entry 变化时打日志 —— `session_usage_codex.rs:1934-1952`

三态 `MissingParent / Stable / Retryable` 由调用方分别构造（`:2201-2212, 2250-2263`），
`Retryable` 还带「父文件 stamp」用于判断「父文件没变就别重试」（`:2144-2168`）。
这是「deferred 是一等状态」在**日志层**的落地：状态没变就不该再喊一次。

### 3.4 缓存与升级

- **Pi 的游标标记换代**（见 3.1d）：换 parser 语义时不重建库，只让受影响 flavor 重扫一次，
  靠持久账本消重。
- **Antigravity 的负缓存**：
  > Steps that need nothing more from the native database for timing: imported with a timing
  > already, or imported and since pruned (the tombstone forbids re-importing them).
  > Keeps steady-state syncs from reopening every conversation database. —— `session_usage_agy.rs:246-248`
  实现是一次 `SELECT EXISTS(session_usage_dedup) AND NOT EXISTS(proxy_request_logs … latency<=0)`
  的批量判定（`:255-271`）。**用账本反推「这个还值得再查吗」，避免每轮打开每场会话的原生库。**
- **MCode 的二级水位**：
  > 单独一遍、带自己的水位：新导入的行和升级前已导入、没有计时的行走同一条路；水位只推过
  > 已经对上、或已超过 TIMING_SETTLE_MS 的行，所以每次同步只回查最近几分钟的行。
  > —— `session_usage_mcode.rs:120-122`（`TIMING_SETTLE_MS = 10 * 60 * 1000`，`:114`；
  > 水位键 `format!("{key}#timing")`，`:147`）
  这是「**已入库的行后来才有补充字段**」的标准解法：第二个游标 + 沉降窗 + 只补不清。

### 3.5 性能结构

- **共享并发额度而不是每批各自限流**：
  > Shared across batches: rows can be tested while another batch is still running.
  > —— `mcp_connectivity.rs:26-28`（`static CHECK_PERMITS: Semaphore::const_new(3)`）
  且注释写明「Queueing here keeps the wait out of the per-server CHECK_TIMEOUT」（`:75`）——
  **超时只计探测本身，不计排队**。测试 `concurrency_limit_spans_batches_and_passes_to_queued_checks`
  专门验「取消第一批后，第二批的排队项才开始跑」（`tests.rs:237-259`）。
- **取消要真的释放**：`AbortHandle` 注册表（`mcp_connectivity.rs:29, 64-99`）+ `KillOnDrop`
  + Unix `ProcessGroup::leader()` / Windows `JobObject` + `CREATE_NO_WINDOW`（`:148-158`）；
  `ProbeProcess::drop` 里 `start_kill()` 之后还要 `wait()`（`:222-235`），理由是
  「A launcher can exit cleanly while its server child is still running」。
- **进程树释放用外部可观测量断言**：
  > `assert_process_released_port()`：等到**端口能重新 bind** 才算子进程死了 —— `tests.rs:289-292`
  这比「相信 Drop 执行过」强得多。
- **极小查询等锁也会卡界面**：
  > 不仅聚合扫描会卡窗口，启动定价同步等小查询等待会话同步持有的锁时也会。 —— `commands/usage.rs:9-11`
  所以 `run_db_query` 把**所有**碰 DB 的 command 都挪进阻塞线程池，而不是只挪大聚合。

### 3.6 破坏性操作与路径形状

**路径别名去重（直接对应我们的一个潜在 bug）**

> A profile directory reached through a link is the same file as its target (symlink, Windows
> junction, 8.3 short name or case-only alias). Listing both spellings made `edit_files_and_commit`
> take the same `<file>.lock` twice, so every provider and MCP write failed with a bogus
> concurrency conflict (#9100). One file is listed once. —— `dsh_config.rs:39-43`

> Stable identity of one native file: its real parent directory plus the file name.
> The file itself may not exist yet … but its parent always does, so resolving the parent is enough.
> —— `dsh_config.rs:62-67`（实现 `:68-76`）

**删除前先证明路径形状**（我们只读，不采纳功能；留作「写入侧」参考）

> `parts.len() == 5 && parts[2..] == ["agents", "main", "wire.jsonl"]`，再 `ancestors().nth(3)`
> 取会话目录，且目录名必须等于 `session_id` —— `session_manager/providers/kimi.rs:317-334`
> tombstone + `.index-dirty` 都是 best-effort，失败只 `log::warn!`（`:343-354`）

### 3.7 测试方法论（对应我们 pending 的「契约式测试」）

- **可编程假服务 + 真协议**：`mcp_connectivity/tests.rs` 用 axum 起真 HTTP/SSE mock
  （`tests.rs:23-119`），stdio 侧用 `rustc` **现编一个 fixture 二进制**
  （`tests.rs:261-282`，源文件 `src-tauri/tests/fixtures/mcp_connectivity_server.rs`），
  注释写「Compiled by the connectivity tests so stdio checks need no Node/Python runtime」。
- **假时钟推进超时**，不真睡：`tokio::time::pause(); tokio::time::advance(CHECK_TIMEOUT)`（`tests.rs:352-359`）。
- **断言副作用而不是返回值**：端口可重新 bind（`tests.rs:289-292`）、跨源主机不得收到消息
  （`tests.rs:154-166`，`assert!(foreign.messages.lock().unwrap().is_empty())`）。
- **共享全局状态的测试串行化**：`#[serial(mcp_check_permits)]`（`tests.rs:212, 236, 306, 340`）。
- **两套取数上限的测试**：`models_dev_size_cap_rejects_oversized_content_length` /
  `models_dev_decode_rejects_decompressed_bomb`（`model_pricing.rs:872-925`）。

### 3.8 外部响应上限（可迁移到任何 fetch）

> 响应大小上限：models.dev api.json 实际几 MB，超限视为异常响应 —— `model_pricing.rs:366-367`（32 MiB）

三段式：`content_length()` 先查（`:397-403`）→ 流式累计再查（`:405-417`，`append_models_dev_chunk`

## 四、建议采纳（对 agent-archive 具体改哪）

按性价比排序。**每条都先量再改**，别照搬上游的数字（8 MiB / 50 MiB 是它的观测值）。

1. **旁路库 enrich「只填不清」+ 前后 stamp 复验**（`src/scanners/codex.js` 的 `enrich`）
   - 现在：每轮按 `state_5.sqlite` 的 `updated_at`/`title` 覆盖会话字段（LESSONS:37）。
   - 改：读不到库/缺列/查询失败时**保留旧值**，不要写 `null` 覆盖；跨文件取真值后重验
     `(size, mtime)` 未变（对照 `session_usage_agy.rs:225`、`session_usage_codex.rs:2050, 2096-2098`）。
   - 收益：一处旁路库抖动不再把标题/结束时间打回粗值。风险低，可先做。

2. **扫描根按「realpath(父目录)+文件名」去重**（`src/scanners/dsh.js:70`、`src/scanners/qoder.js:81,91`）
   - 现在：`if (isDir(...) && !out.includes(r))` 是**字符串比较**。junction / 8.3 短名 / 大小写
     别名会让同一目录进两次 → 同一批会话扫两遍、同一个文件两次写进 `sources`
     （`registry.js:658`），正文读取会重复拼接（未证实实际发生，未量；但判定逻辑成立）。
   - 改：照 `dsh_config.rs:68-76` 的 `path_identity()`，Windows 上用 `fs.realpathSync.native`
     （会展开 8.3 与 junction）取父目录，join 文件名做 key。
   - 收益：去掉重复解析与重复来源；成本 < 30 行。

3. **任何「文件太大」的兜底都加在记录粒度**（`src/scanners/claude-code.js:110,327`、
   `src/scanners/antigravity.js:331`、`src/scanners/codex.js:507` 都是整文件 `readFileSync`）
   - **先量**：统计我们实际最大单文件 / 最长单行（目前台账只有「索引正文 169 MB / 3102 场」，
     没有单文件分布 —— **未证实**是否需要改）。
   - 若需要：照 grok 的形状做「逐行读 + 单行上限，超长行丢弃但计数、不放弃文件」，
     **不要**加「整文件超 N MB 就跳过」（`session_usage_grokbuild.rs:148-152` 明确说那会整段漏记）。
   - 附带一条零成本的：`readTailEnd`（`codex.js:354`）读尾时若首行被切断要像现在这样跳过，
     并且**不把被切断的尾行计入行数**（同 `session_usage.rs:625-628` 的半行纪律）。

4. **doctor 的失败分类改成三态 + 变化才告警**
   - 现在：`failures` 计数 + `postProcessErrors`（`registry.js`），"读不到正文"没有独立状态。
   - 改：照 `session_usage_codex.rs:1923-1957` 的 `MissingParent / Stable / Retryable`：
     缺父会话、正文不可读、解析失败分开计数；状态没变化就不重复告警。
   - 与 LESSONS:185（Elysian 的 deferred 一等状态）是同一件事，可以一次做掉。

5. **扫描器升级只重扫受影响 Agent，靠 session key 幂等**（`src/registry.js` 的 `__fingerprint`）
   - 现在：任何扫描器内容变化 → `__fingerprint` 变化 → **全量重扫**（LESSONS:142）。
   - 改：把 `__fingerprint` 从「全局一个」拆成「每个 Agent 一个」，只有内容变了的 Agent 重扫；
     并在测试里断言「重扫前后总量不变、复制品仍被合并」（对照 Pi 的
     `old_cursors_rescan_once_without_changing_existing_history` 的 `(0,2)`→`(0,0)`）。
   - 注意：这条的收益取决于单次全量重扫的耗时（台账写 2.17s→1.02s 是热扫），
     全量重扫只发生在改代码后，收益中等。**先量再决定**。

6. **`findVersionedDb()` 之外补一条「同一文件名、两个目录」的候选**
   - 现在：`src/sqlite-read.js:206` 按前缀取最高版本，比 cc-switch 强（LESSONS:121-123 结论不变）。
   - 可补：Codex 的 `sqlite_home` / `CODEX_SQLITE_HOME` 会让 `state_5.sqlite` 出现在
     `~/.codex` 之外（`codex_state_db.rs:24-36`）。我们目前只按 `~/.codex` 找。
     这不是「文件名写死」的问题，是**目录可迁移**：值得核一下我们是否漏了这条路径。
     属于**覆盖面缺口**，不是方法论缺口。

7. **外部取数的三段式上限（为将来接 GitHub API fallback 备用）**
   - `src/pricing.js:136-147` 的 `syncCatalog` 现在只有 `res.ok` 检查，**没有大小上限、
     没有超时、没有编码校验**。照 `model_pricing.rs:366-455` 补：
     content-length 预检 → 流式累计上限 → 解压后同一上限 → 不认识的 `content-encoding` 报错。
   - 我们目前只有 `pricing.js` 会发 HTTP（`refresh.mjs` 走 git），这条是预防性的，成本低。

## 五、明确不采纳及理由

| 事项 | 为什么不采纳 |
|---|---|
| 汇率显示 / 币种换算（`exchange_rates.rs` 整个文件） | 产品功能。只取其「多源回退 + 汇总失败 + 空即失败」的形状（见建议 7 的同类） |
| MCP 连通性探测（`mcp_connectivity.rs`） | 产品功能；我们只读 `.mcp.json`，不向任何 server 发起握手。只取「超时不计排队」「取消要真释放」两条结构 |
| 会话删除 / tombstone / `.index-dirty`（`providers/kimi.rs`） | 只读档案馆不提供删除。留作写入侧参考 |
| 写用户配置文件（`claude_editor.rs` 的 `switch_drops`、`provider/mod.rs` 的 `lock_native_provider_operations`、`live/`、`mode/`） | 存在前提就是「改用户配置」，对我们全是攻击面 |
| 定价种子表（GPT-6.1 Terra、Grok 4.6/4.7 等，`database/schema.rs` 的 `INSERT`） | 供应商预设/价目表。我们价目从 models.dev 同步，不内置 |
| Codex 逐请求 delta 计价（`session_usage_codex.rs` 的核心逻辑） | 维持不做（LESSONS:145）。本轮它又加了一层 bounded fork 验证，进一步说明口径复杂度 |
| 前端 FlexSearch 元数据搜索（`useSessionSearch.ts`） | 我们正文可检索（FTS5），比只索引元数据强，没有可抄的 |
| `run_db_query` 的线程池模型 | Tauri 的「命令跑在主线程」是它独有的约束。Node 单线程的对应问题是「同步扫描阻塞事件循环」，我们已用预热 + 缓存处理，不引 worker（成本 > 收益，未量） |
| i18n / 预设域名迁移 / release notes / CI（76 个提交里约 20 个） | 判断标准明确排除 |
